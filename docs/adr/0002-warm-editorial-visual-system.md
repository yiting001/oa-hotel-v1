# ADR-0002: 采用暖奶油 + 珊瑚的编辑式视觉体系

- 状态：已被取代（见 ADR-0003）
- 日期：2026-09-24

## 背景

ADR-0001 定下了组件库策略（新平台模块用 Element Plus，存量页面逐步迁移），但没有约束视觉语言本身。此前应用外壳是「深色侧栏 + 深墨后台」的青绿体系：`html.dark` 在已登录路由上常驻，Element Plus 的暗色变量表主导外观，ant 主题另有一份深色 token，两处取值互不相干。

结果是三件事同时发生：同一套令牌在浅色与深色各写一份、页面里散落的深色写法（流程节点画布、图表内联色）在浅色模式下已经是坏的、以及「品牌感」完全依赖组件库默认值。

## 决策

1. **统一为单一暖色浅色主题**：页面底色为暖奶油 `#faf9f5`，主色为珊瑚 `#cc785c`，骨架与强调块用深墨 `#181715`。删除常驻的 `html.dark` 与 Element Plus 暗色变量表，`EChart` 不再按 `.dark` 类切换主题。
2. **令牌只有一个出口**：颜色、字体、字号、间距、圆角、阴影、Element Plus 映射全部定义在 `apps/web/src/styles/foundation.css`；组件级覆写集中到 `apps/web/src/styles/components.css`，按组件语义写而不按库写。
3. **两个组件库共享一套外观**：ant-design-vue 通过 `app-config.ts` 的 ConfigProvider token 接入，Element Plus 通过 foundation.css 里的 `--el-*` 接入。两处取值必须与 foundation.css 同步。
4. **canvas 渲染器运行时读令牌**：ECharts 注册 `oa-warm` 主题、LogicFlow 节点色通过 `shared/design-tokens.ts` 读取 CSS 变量，不再出现内联色板。
5. **打印面与屏幕面隔离**：单据打印页与 A4 设计器纸面固定为白纸黑字（显式中性色 + 宋体），只让屏幕外壳跟随主题。
6. **标题走衬线、正文走人文无衬线**：显示体字重固定 400 并收负字距；不做 600/700 的显示体。
7. **版面骨架改用发丝线分段**：顶栏降为面包屑工具条（页面大标题只在页头出现一次）、页头以一条通栏发丝线收尾、指标带用上下线与列间竖线而不是卡片、表格直接落在画布上（表头只留底线）、单据表单以「顶部发丝线 + 衬线小标题」分区、右侧流程栏改为一条竖线分隔的窄列、空状态改为排版式短句（不用组件库插画）。目的是让版面靠线与留白组织，而不是靠一层层盒子。

## 后果

- 页面级样式只需引用变量即可跟随换肤；本轮的页面改动集中在排版（衬线标题、间距节奏、圆角与表面分层），而不是逐个页面重写。
- 不再提供深色模式。若将来要加，必须在 foundation.css 里以**第二套令牌**的形式整体引入，不能恢复「部分页面写死深色」的旧做法。
- 显示体依赖系统衬线族（中文落到宋体族），不引入 Web 字体：离线与内网部署不需要额外资源，代价是不同操作系统的衬线字形略有差异。
- Element Plus 的表格固定列、页签选中态等依赖组件库内部变量，覆写时必须走库自己的变量（例如 `--el-table-tr-bg-color`），直接改元素背景会让固定列与滚动内容叠字。
