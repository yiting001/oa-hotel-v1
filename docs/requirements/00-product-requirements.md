# 企业级 OA 产品需求

## 1. 产品定位

本系统不是若干固定审批页面的集合，而是由“组织权限 + 动态表单 + 工作流 + 业务单据 + 门户协同 + 审计归档”组成的企业级 OA 平台。

首期服务约 200 名用户，覆盖 PC、平板和手机。系统应允许后续增加酒店、部门、岗位、审批规则和表单，而不修改工作流内核。

## 2. 产品目标

- 统一员工制单、审批、阅办、通知和归档入口。
- 将合同、支出、印章、采购、财务、人事、公文和党群流程线上化。
- 保留原需求文档中所有表单字段，并为字段补充数据类型、校验和权限。
- 支持复杂审批：条件分支、会签、退回任意历史节点、补件重提和跨流程联动。
- 提供漂亮、清晰、响应式的门户和工作台。
- 提供可打印、可归档、可审计的完整业务凭证。

## 3. 用户角色

角色是权限集合，不直接等同于人员。人员通过组织岗位获得角色，流程节点通过规则解析办理人。

| 角色 | 主要能力 |
| --- | --- |
| 普通员工 | 发起本人可用流程，查看本人单据、待阅和通知 |
| 部门秘书 | 代部门制单、选择会签部门、维护部门材料 |
| 部门总监 | 审批本部门业务、决定是否会签或升级 |
| 财务秘书 | 财务预审、补件退回、分配财务处理路径 |
| 财务主管/总监 | 财务专业审批、审计判断、金额及科目审核 |
| 办公室秘书/主任 | 行政预审、会签组织、用印与公文协调 |
| 总经理 | 高权限审批、退回指定历史节点 |
| 业主负责人/代表 | 业主方审批或最终确认 |
| 印章管理员 | 用印、外借、归还和归档登记 |
| 采购/库管 | 采购询价、领用实发和库存处理 |
| 人力资源 | 假期规则、员工档案和请假归档 |
| 党办/党委角色 | 党群发文、收文、印章和“三重一大”流程 |
| 流程管理员 | 表单、流程、节点、版本和运行实例管理 |
| 系统管理员 | 组织、用户、权限、字典、编号和系统配置 |
| 审计员 | 只读查询流程、业务数据、打印记录和审计日志 |

## 4. 产品范围

### 4.1 平台能力

1. 身份认证与会话管理。
2. 公司、部门、岗位、用户、角色和数据权限。
3. 表单定义、表单版本、字段规则和响应式布局。
4. 流程定义、发布、版本、运行、任务和审批动作。
5. 待办、已办、我发起的、抄送、待阅、草稿、关注和批量审批。
6. 附件上传、预览、下载、版本和归档。
7. 消息中心、站内信、待办提醒和超时催办。
8. 门户、个人工作台、信息发布和常用入口。
9. 全文检索、组合筛选、统计和导出。
10. 打印模板、审批意见汇总、二维码验真和电子归档。
11. 审计日志、操作留痕、异常追踪和备份恢复。

### 4.2 业务模块

- 合同与支出
- 行政办公与印章证照
- 物资申购与领用
- 财务支出、借款与退款
- 人力资源请假
- 会议宴会与 EO 协同
- 信息发布
- 公文收发
- 党群工作

### 4.3 后续扩展

源文档页面中还出现内部用房、资产维修、资产领用/归还、鲜活食品申购、工会支出等入口，但未提供完整字段和流程。先登记为扩展模块，不在首批验收范围内。宴会会议工作单已通过 EO11.pdf 补齐表单字段，纳入会议宴会模块。

## 5. 核心业务对象

| 对象 | 说明 |
| --- | --- |
| 业务单据 | 用户填写的合同、支出、请假、公文等领域数据 |
| 表单定义 | 字段、布局、校验、可见性和计算规则 |
| 流程定义 | 节点、连线、办理人、条件、动作和时限 |
| 流程实例 | 某张业务单据的一次审批运行 |
| 任务 | 分配给某个办理人或候选组的待办工作 |
| 审批意见 | 审批动作、意见、签名、时间和节点快照 |
| 附件 | 与单据、节点意见或归档包关联的文件 |
| 归档包 | 表单快照、流程轨迹、意见、附件和打印版本 |

## 6. 关键产品规则

1. 单据保存为草稿时不创建流程实例，提交成功后才锁定表单和流程版本。
2. 流程运行期间可按权限补充附件，但不得静默覆盖已审批字段。
3. 业务字段修改必须生成修订记录，显示修改人、前值、后值和原因。
4. 所有意见在表单底部按时间或节点顺序完整展示，并进入打印归档。
5. 退回必须记录目标节点和原因；重新提交后保留原历史，不覆盖旧任务。
6. 会签节点必须明确通过规则：全部通过、按比例通过或指定角色通过。
7. 金额统一使用最小货币单位存储，展示时格式化，禁止浮点计算。
8. 编号由编号规则服务生成，不能在业务代码中拼接固定字符串。
9. 删除采用业务作废或软删除；已提交、已审批和已归档数据不可物理删除。
10. 流程配置发布后不可原地修改，只能复制为新版本。

## 7. 非功能需求

### 7.1 可用性

- 常用页面首屏加载目标不超过 2 秒。
- 手机端单手可完成查看、填写、审批、退回和附件操作。
- 表单自动保存草稿，网络恢复后允许继续编辑。
- 错误信息面向业务用户，不暴露堆栈、SQL 或内部标识。

### 7.2 安全

- 最小权限、数据范围隔离、敏感字段脱敏。
- 登录限流、密码安全策略、会话撤销和可选双因素认证。
- 文件类型、大小、病毒扫描和下载权限控制。
- 所有审批动作要求服务端再次鉴权，禁止只依赖前端按钮控制。

### 7.3 运维

- SQLite 适合首期单实例部署；必须启用 WAL、定期备份和恢复演练。
- 数据访问通过仓储接口隔离，为后续迁移 PostgreSQL 保留空间。
- 提供健康检查、结构化日志、指标、告警和数据库迁移。

## 8. 明确不做

- 首期不做低代码平台的任意脚本执行。
- 首期不做复杂 BPMN 全标准兼容。
- 首期不做财务记账系统，只完成审批和财务数据交接。
- 首期不做无需求依据的酒店经营、库存或人事全套 ERP。
